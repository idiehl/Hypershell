# HyperLib content store

`ContentStore(rootPath)` owns content only. The gateway calls `InitializeAsync`, reads a `LibraryState`, and submits an `OperationBatch` with that state's `expectedRevision`. All operations in a batch either commit together or make no change. A `ConflictException` means the caller must reload before retrying; it must never blindly replay a stale edit.

`savePage` also requires the supplied Page's `revision` to match the stored Page revision. Preserve it from the page that was read. This prevents a stale page snapshot from overwriting a newer page even if a client has refreshed the outer library revision. When importing a library folder without its journal, initialization preserves valid `Content/library.json` content and revision and starts a fresh history from it; malformed imported content stops initialization instead of seeding over it.

The library root is implicit (`state.libraryId`); only Collections may be its children. Canonical hierarchy types are `collection`, `series`, `work`, `volume`, `part`, `chapter`, `page`. Optional levels may be skipped, but every Page and every level below Work needs a Work ancestor. Display labels never change these types. IDs are stable across rename/reorder/move. Cross-Work Page transfers are rejected because template contracts can differ.

`createNode`, `updateNode`, `moveNode`, `deleteNode`, `savePage`, `setAppearance`, and `setLabels` are the complete mutation vocabulary. A new Page receives starter content when `page` is omitted. `updateNode.cover = ""` clears its optional cover; omitted fields are preserved. Appearance assignments replace the settings object; label assignments merge named labels. Deleting a node removes its descendants as one undoable operation.

Immutable `.hyperlib/journal/{revision:D20}.json` records are the commit point. They contain checksummed before/after snapshots and sufficient transaction identity to reconstruct undo/redo after restart. A flushed temporary record is renamed atomically without replacement. `Content/library.json` and the `Library/` directory tree are readable projections, regenerated from committed history after an interrupted write. Incomplete temporary records are ignored. A damaged committed record stops safely with `ContentRecoveryException`; it is never silently discarded or replaced. External edits to projections are not imported while a journal exists.

The hierarchy physically projects organizational nodes as directories and Pages as JSON files. The relative location is available as `node.directoryPath`. Renamed/deleted projections move under `.hyperlib/retired/` so incidental user files are preserved. Work source projects remain at stable `Works/{workId}` paths and are never deleted by content operations. Runtime project creation happens after the content commit; it is not part of this store.

Each Work also contains `Works/{workId}/Content/work.json`: a non-authoritative snapshot of that Work's nodes and Page documents, their paths relative to its code project, and its referenced central media. The same `Content/` directory contains the actual Page JSON documents inside the Work's optional Volume/Part/Chapter folders. This makes the Work's authored documents physically visible beside its source code while retaining the complete Library hierarchy projection. Media remain deduplicated in the Library's central `Media/` directory; the snapshot records both library-relative and Work-relative links. These projections do not make a Work independently exportable: the portable unit remains the complete HyperLib folder, including shared runtime code and media. Missing projections and older projection formats repair from the journal without changing content revisions.

`UndoAsync(expectedRevision)` and `RedoAsync(expectedRevision)` undo/redo the latest complete content batch, assign a new monotonically increasing library revision, and retain media and source projects. A new normal edit clears the redo chain. Changed Page revisions also increase. This is ordered history, not selective undo of an older AI action over intervening edits.

Set `TemplateResolver` to return each Work's **active compiled** `TemplateDefinition`, not its currently edited source. Existing Works always prefer that active, independently owned contract. If no active contract exists, a Work with `starterId` uses its catalog definition; legacy Works without it use `StarterTemplate.Create()`. `TemplateValidator.EnsureCompatible(candidate, pages)` rejects incompatible activation without rewriting content. Field labels may change; stable field IDs preserve values; additive fields can declare defaults. Schema validation does not authorize executing arbitrary code: compiled Studio code belongs to the trusted runtime, while content contains typed values only.

## Reusable base templates

`BaseTemplateCatalog.List()` (also `Catalog`) returns metadata for seventeen permanent starters: the original Woodland Editorial and Wave Laboratory plus fifteen new designs. Metadata includes `id`, `title`, `description`, `category`, `demoTitle`, `isOriginal`, and `background`/`accent`/`ink` preview colors. `CreateTemplate(id)`, `CreateAppearance(id)`, and `CreateDemoPage(id, pageId, workId, title?)` return independent, validated copies. Catalog availability alone does not add pages to the library; the separate installer materializes demo Works and source packages.

Work creation accepts an optional `starterId`, defaulting to `woodland-editorial`. Only `createNode` for a Work may supply it; later changes to the owned template happen in Studio. The selected ID is persisted on the Work. When present, `BaseTemplates/{starterId}/Project/authoring.template.json` is the canonical reusable schema, including Studio edits; the built-in catalog supplies a fallback only when that file is absent. The path must remain inside the library without reparse points, and malformed schemas stop creation rather than silently reverting to shipped defaults. Its appearance defaults are overlaid by any supplied local settings. Pages created later in the **same batch** share that validated starter snapshot, even before a renderer project exists. A later content operation always checks the active owned template first. The store never writes or replaces template source files.

`TemplateDefinition.defaultBlocks` contains the complete ordered Add Page content. Copies retain stable block IDs, regions, and field values, and the first header/banner title becomes the requested Page title. Empty default lists preserve the legacy single-block behavior. Default blocks themselves are validated, including region membership, unique IDs, field types, and safe URL/select/color values. Original catalog defaults retain the six original content blocks, surrounded by editable header, divider, and footer blocks; existing authored pages are not rewritten by the catalog.

Pages created from nonempty defaults set `usesEditableChrome: true`: their headings and footers are ordinary editable blocks, so deleting a heading does not make an automatic one reappear. Legacy pages omit the flag and can retain their implicit heading until explicitly migrated. False remains omitted during JSON serialization to preserve checksums of existing journal records; undo can restore that legacy behavior along with old content.

All built-in blocks expose optional `span` (`full`, `half`, `third`, `two-thirds`), `font` (`system`, `serif`, `monospace`, `humanist`, `geometric`), `align` (`left`, `center`, `right`, `justify`), and hexadecimal `color` fields. Omitted values inherit the page presentation; omitted span means full width. Page/Work appearance declares full-page `background`, `accent`, `ink`, `surface`, `muted`, body `font`, `headingFont`, and a catalog `variant`. Reset a local appearance override by removing its key and submitting the remaining dictionary.

The shared palette includes header, footer, banner, divider, form, map, embed, and interactive tool blocks alongside the original text/media/experiment blocks. Their fields are typed content, not HTML, CSS, executable scripts, or a form destination. Renderers own safe map/embed activation and local form/tool behavior. New demo illustrations use `/media/base-templates/{starterId}.svg`, provisioned by the template installer; original examples retain their existing bundled media.

Appearance values are validated against the appropriate active template: package `library` for Library/Collections/Series, the owning Work package for Works and their descendants. Unknown fields, wrong types, invalid select options and out-of-range values are rejected. Candidate activation should use the three-argument `EnsureCompatible(candidate, pages, appearances)` overload so used appearance controls receive the same compatibility protection as page fields.

`ImportMediaAsync` streams supported images/audio/video/PDF into `Media/`, enforces a 64 MiB default limit, checks MIME/extension/signature, and uses a SHA-256 filename. Paths, alternate streams, traversal and reparse points are rejected. Active document formats (HTML/SVG) are not accepted through upload. Trusted bundled illustration assets may be shipped separately. `MediaAsset.url` is the stable gateway URL; metadata records retain the user's original filename.

Source citations are stored with Page content, including URL, title, retrieval time, provider, verified status and block associations. The store preserves provenance supplied by the native research coordinator; it does not independently fetch or certify sources. The seeded further-reading reference is explicitly unverified.

Run the console verifier from the repository root:

```powershell
dotnet run --project Hyperlib/tests/HyperLib.Core.Tests/HyperLib.Core.Tests.csproj --artifacts-path Hyperlib/.hyperlib/core-build -- Hyperlib/.hyperlib/core-tests
dotnet run --project Hyperlib/tests/HyperLib.Catalog.Tests/HyperLib.Catalog.Tests.csproj --artifacts-path Hyperlib/.hyperlib/catalog-build -- Hyperlib/.hyperlib/catalog-tests
```

The verifier leaves its isolated fixture directories beneath the supplied artifact path for inspection.
