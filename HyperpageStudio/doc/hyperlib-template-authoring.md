# Hyperlib Editor and reusable templates

A **Template** is a reusable element library: text boxes, media boxes, widgets, tools, and their editable fields. A **Work** contains Pages and organizational containers, and defines page layout, regions, Work-specific elements, and shared appearance. A **Page** supplies content and arranges those elements in Hyperlib.

Choose **+ → Hyperlib Editor** in Hypershell to open the configured library directly. The dedicated workspace starts in **Templates**, with Studio's source editor and authoring tools available when needed. Opening the HyperLib root manually also shows the same template manager.

In **Template**, search element libraries and select one to see its details. **New template** opens the **Core Template Library** so you can collect objects and name the new Template in one place. A named empty collection creates a minimal Template with a basic text element and no starting Page content. **Customize element library** makes an independent copy of a built-in library; **Duplicate** copies one of your templates. **From Work** captures an existing Work's authoring definitions for reuse. These operations leave page content in its original Work. **Edit elements** opens Elements and their field definitions first. Layout, regions, style schemas, and source remain available as advanced tools.

The **Core Template Library** organizes complete design collections as **Design Groups**. Existing built-in and custom Templates are copied into independent Groups the first time the library opens. Their original projects remain available. Groups retain their source and do not depend on the original Template remaining installed. Changes to an original Template do not silently change its Group; use **Save as Design Group** after saving a Template to publish another collection.

Browse a Design Group or search across the library, then filter by use: text and content, media, structure and navigation, decoration, widgets and tools, page layouts, typography and fonts, colors and surfaces, or Work styles. Select an object to see its actual Razor rendering in a sample Page. First preview of a source collection compiles a separate renderer; subsequent objects reuse it. The preview includes component styles and local assets. It is a visual sample; interactive widgets run in a Work.

Use **Add to collection** for each desired object, then **Add to Template** in an existing Template or **Create Template** for a new one. You can collect from several Design Groups. Individual elements use the destination's colors and typography. Configured examples retain their field values; fonts, palettes, and complete Work styles are separate choices. A layout brings its required elements and replaces the starting arrangement for future Pages. Select one layout per addition; existing Page content stays in place.

Imports bring local component source, nested helpers, scoped styles, and assets along. Shared stock source is reused; differing source receives unique component names and asset paths to avoid collisions. The collection stays in the editor draft until **Save**. Saving checks source changes and destination conflicts before publishing the new definition. Dependencies on external projects are reported rather than silently producing an incomplete import; additional assembly or package references must already be available in the destination.

**Create Work** creates an independent Work and its Home page from the selected Template. Choose a collection or series for the Work, then name it. **Open Work** opens its own Editor context. **Contents** shows Pages nested in Volumes, Parts, and Chapters; container creation offers only valid locations in the selected Work. **Write in Hyperlib** opens the Work's writing workspace, where authors create and fill Pages on the fly. **Write Page in Hyperlib** opens an existing Page directly. Rename, undo, and redo use the same validated library operations as Hyperlib. Undo and redo operate on library content history, including changes made outside Studio; they do not undo local template creation or template source edits. A stale session must refresh before trying again.

Within a Work, use **Contents** for its hierarchy, **Structure** for Page layout, regions, and special elements, and **Appearance** for default colors, fonts, and text size. The **Page** area provides a lightweight handoff to Hyperlib writing. Advanced source and preview actions remain available; preview starts only on request and keeps the active renderer alive while visible.

A Work is an independent application project with its own components, styles, scripts, and template definition. Existing pages share that design, so a compatible component or styling change can update them together without replacing their content. Changes to the starter do not flow into already-created Works. New-page defaults affect future pages only. The current release still uses the library gateway for content storage, editing, and hosting; a project opened away from its library can edit its design but cannot browse or mutate missing library content.

The element-library and Work-structure editors retain four compatible sections, with Elements primary for Templates and layout/regions primary for Works:

- **Elements:** add from a component already available in the Work, duplicate an existing element, edit its exposed fields, or open its component source. Duplicates have independent stable IDs and share the existing renderer component.
- **New page defaults:** add, remove, reorder, and configure the initial element instances used by Add Page. These changes do not replace content on existing pages.
- **Styling controls:** expose supported colors, fonts, layout design, element width, and alignment. Appearance defaults are fallbacks; explicit page, Work, and library values take precedence. Custom fields require a corresponding renderer binding; declaring a field does not generate arbitrary CSS.
- **Regions:** choose which elements can be used in each region. “Allow all” includes future element additions.

Field defaults distinguish inheritance, an explicit value (including an empty text string), and explicit null. Options are individual exact values, so commas in font names are preserved. Element, field, region, and instance IDs stay stable when labels change.

Saving checks the current library's pages and appearance settings before writing the template source. Incompatible removals are rejected without changing content. External source edits are detected rather than overwritten. HyperLib then builds and checks a candidate renderer; the last working version remains active until the candidate passes. Offline projects without a library content index receive template validation and are checked against content when HyperLib activates them.
