# Handoff feature coverage

Status: 9 October 2026, updated for unified single-item Media content, bounded/unbounded Display Patterns, Freeform radial placement and drag-to-nest previews, plus per-window Ctrl+C/Ctrl+V branch copying with fresh GUIDs and collision-free paste, persistent link tracing, compact Utility Pivot/Joint nodes and editable link line styles, shared canvas/node background presets and embedded raster uploads, one-object Gallery containers and six inspector panels, editable node identities, conceptual GUID links, supplementary attachments and hyperlinks, and backdrop-aware collision and sticky edges. This cycle adds default Single select with a Hand area-selection dropdown, Shift-constrained link tracing, centered text defaults, proportion-preserving regular backdrops and safe shaped content, and selection overlays aligned at every border thickness. Home and other canvases share the same persistent tools and adaptive creation forms. Single-click inspection and double-click disclosure remain in the same canvas. This is an implementation audit of the current code against the functional identifiers in `Atlas_Meridian_Project_Handoff_v0_9.pdf` (pages 2–22), checked alongside its open decisions (pages 23–27) and historical conversation. It is not a claim that the entire handoff is complete. The PDF's historical material and proposed acceptance examples do not automatically become implemented behavior. The current user explicitly puts online publishing, the online repository and accounts/login last; those are separated from the remaining local work below. Installed package/version evidence belongs in the cycle's completion report, not this source-coverage table.

**Implemented** means the stated capability exists within the current local Boolean and finite-number product. **Partial** identifies the specific boundary. **Deferred** means the named capability has no complete product workflow yet. **In progress** identifies current work that must not be called shipped until implementation, verification and installation are complete. Later entries distinguish broad requirements from their implemented subset. This audit inspected source and test coverage; test names alone are not a claim that tests were executed during this audit.

## Local milestones and remaining priorities

These priorities follow the current request to improve major features and make editing intuitive. Confirmed capabilities are distinguished from implementation conveniences and optional proposals.

1. **Selection, grouping and viewer snippets — completed local foundation for N14/N04/N47 and N64, pages 5, 14, 17 and 21.** Multiple selection, region selection, whole-selection movement and same-parent grouping work. The editor now uses its Module Library to reuse selections, with no selection/download strip; portable viewers retain selected-copy downloads. Escape finishes direct text editing and clears canvas selection. Right-click Lock/Unlock Position persists an anchor while keeping text editable, and also constrains branch and rigid Cluster movement. A separate snippet extractor preserves/remaps the selected graph and gives explicit descendant and external-snapshot choices, with boundary counts. Arrange now adds six alignment actions and horizontal/vertical equal spacing as one undoable branch movement. This extends the existing one-root module workflow rather than confusing the two. Specific shortcuts and menus are implementation choices under D06. Broader arrangement, direct placement and media-entry improvements remain useful follow-up work; the entire editor is not declared complete. See [ARRANGEMENT.md](ARRANGEMENT.md).
2. **References between independently saved local canvases and complete chosen dependency packages — N03/N18/N52/N57–58/N62–63, pages 2, 6 and 19–21.** Current resolution is bounded by the opened project's graph and saved snapshots. A local-library GUID lookup, original-context navigation and save-triggered consumer refresh remain to be built. External-inclusion controls currently include available snapshots, not an entire external canvas and its operating context. Viewer snippets now offer the inclusion choice; the whole-publication Save a copy workflow still preserves the original policy. These are local capabilities; they need not wait for accounts or public hosting. Existing revision/recovery protections and read-only ownership must remain binding.
3. **Coordinate-addressed cell containers — implemented local foundation for N09, page 5.** The spreadsheet surface, persistent coordinates/names, cell creation and inspection, nested spreadsheet/document cells, CSV/TSV embedding and grid/row/column/radial/staircase/free child arrangements now exist. Variable child sizes remain authored; layout moves complete branches and accounts for expanded nested grids. Spanning and workbook calculations remain open; the handoff explicitly does not specify formulas. See [GRID.md](GRID.md).
4. **Complete media viewing and easier media authoring — N02/N07, page 2; D07, page 24.** Raster, TXT/MD, browser PDF and native attached video work. SVG is not rendered as media, and DOCX is preserved but only downloadable to another application. Integrated document viewing, a persistent media pane and easier local placement are useful next steps. Exact editing fidelity and writing back to media originals remain open. Any SVG support must preserve the inert authored-content boundary.
5. **One canvas interface — completed local foundation for N01/N43–46.** Home now stores a full ordinary node graph, uses the same persistent tools and adaptive forms, and supports media, authored visual links, working nodes, autosave and checkpoints. Embedded Canvas launchers navigate in the current window with Back and Forward. Legacy groups migrate to Containers with identity, hierarchy and geometry retained. Optional descriptive Canvas imagery remains a useful future improvement. See [UNIFIED-LIBRARY.md](UNIFIED-LIBRARY.md) and [WORKSPACE-TOOLS.md](WORKSPACE-TOOLS.md).
6. **Specific inherited-rule impact preview — completed local milestone for N55, page 22.** Named node, connection and operation choices replace raw comma-separated fields. Each category explicitly inherits or narrows its allowance, with ancestor exclusions disabled. The preview identifies changed descendants, hidden status, before/after permissions and actionable conflicts before Apply. Existing validation rejects incompatible changes atomically. N15's extensible system/domain behavior and D05's broader compatibility policy remain separate future work.
7. **A coherent continuous-signal milestone — N27–29/N32/N34, pages 11–12.** Pure tones, waveform generation, layered signals and effects, waveform observation, audible destinations and parent-scoped continuous execution remain absent. The existing runtime only supports Boolean and finite-number values. This is a major confirmed feature family. It needs a typed stream model, visible scalar controls, explicit joint operations, closed/open circuit lifecycle, independent sibling outputs and real Run/Stop All behavior. Timing, phase/reconnection, stream references, saved signal observations, levels and resource policy are open in D11–D13 and should be settled as one coherent design. The broad Max-inspired catalog on page 13 is a proposal, not a promise of Max parity or engineering-grade electrical simulation.

**Final online phase:** online deployment/selective publication, accounts/login, personal/community repositories, audience/permission controls and shared collaboration (N39–N41, online portions of N37/N42 and D14–D18). They are explicitly postponed by the latest user instruction. Existing local HTML publication and editable packages remain useful and do not mean that this online phase is complete.

The handoff does not approve every proposal in its transcript. In particular, page 22 says the advanced result-inspector, pause, single-step and value-history bundle was not accepted; page 13 labels the extended component catalog optional; page 27 leaves module tags, thumbnails and versions as proposals. These should not displace confirmed missing requirements without a new product decision. True multiple containment, full feedback semantics and separate variable namespaces also remain open choices, not already implemented features.

## Density and navigation implementation boundary

`src/core/navigation.ts` supplies display bounds, cycle-safe ancestry/outline/backlinks/original resolution and document search. `src/scene.ts` uses those bounds consistently for rendered cards, fit calculations, connection endpoints and snapping. `src/editor.ts` and `src/viewer.ts` share the same scene; optional spatial parent and child-placement fields survive saves and publication; cameras remain view state.

Unbounded parents fit their single content item independently of child disclosure. Appearance offers Automatic or Fixed sizing; new nodes use Automatic. Children can be adjacent, connected, or distant on the same canvas. Freeform places new automatic children in balanced radial rings and translates their complete branches and internal route points together. Manually dragging a child records its position without changing its descendants’ placement choices. Bounded Freeform parents preserve a working interior around visible branch envelopes; Display Pattern changes retain node IDs, addresses and independent disclosure states. Explicit Fit selected branch frames visible descendants; ordinary disclosure never fits the camera. See [NODE-SIZING.md](NODE-SIZING.md) for sizing, Grid capacity, Gallery paging and compatibility.

Search decodes included TXT/MD assets once per search index, beyond the 3,000-character card preview. Complete TXT/MD dialogs use inert text content. Search does not OCR images or extract PDF/DOCX contents. An editor search result may expand ancestors as one undoable document edit. Viewer navigation, collapsed state and control changes only affect its runtime clone; its embedded data and Save a copy output remain authored data.

Camera positions are remembered per canvas while a project remains open. They are not persisted in the project file. Editor discovery is now in the right panel: empty search renders no outline, and Contents lists the selected parent's direct children. Full search still reaches hidden descendants and reveals a selected path; cross-canvas discovery updates the URL for reload. Viewer history tracks canvas/node contexts, while per-canvas cameras remain separate view state. The viewer Explore panel is a responsive drawer and does not change the initial framing of a publication. Closed descendants are omitted from its large outline displays. This reduces closed-hierarchy DOM cost without claiming a fully virtualized canvas. See [RIGHT-PANEL.md](RIGHT-PANEL.md) and [MEDIA-WINDOWS.md](MEDIA-WINDOWS.md).
